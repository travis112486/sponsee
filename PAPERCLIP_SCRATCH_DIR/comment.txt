## SPO-30 fixes applied — requesting QA re-verification

All five QA blockers have been corrected.

### Fixes delivered

**P1 — Mailpit delivery path** (`apps/api/src/email/mailpit.ts`)
- Changed from form-data POST `/api/v1/message` → JSON POST `/api/v1/send` per Mailpit API docs.
- Added conditional real-Mailpit acceptance test: probes `localhost:8025`; if available, sends a real message and asserts it lands in the inbox.

**P1 — Durable approval/enqueue boundary** (`apps/api/src/routers/chase.ts`)
- `approve` and `editAndSend` now wrap `boss.send` in `try/catch`.
- On enqueue failure, status is reverted from `approved` → `awaiting_review` so the creator can retry.
- Added integration tests covering both `approve` and `editAndSend` enqueue-failure rollback.

**P1 security — Webhook verification** (`apps/api/src/email/postmark.ts`, `resend.ts`, `types.ts`)
- Removed the unsigned-webhook fallback (`if (!secret) return true`). Both providers now reject all webhooks when no secret is configured.
- Postmark: replaced invented `x-postmark-signature` HMAC with HTTP Basic Auth verification (`Authorization: Basic …`), matching Postmark's documented webhook auth.
- Resend/Svix: added 5-minute timestamp tolerance and replay protection; still rejects when secret is absent.
- Added unit tests for each verification path (valid signature, missing secret, stale timestamp, invalid signature).

**P1 — Gate commands green**

- `pnpm lint` ✓ (0 errors)
- `pnpm test` ✓ (160 tests: 144 API + 16 web)

**Root cause of test instability discovered and fixed:**
- API integration tests set `process.env.VERCEL = "1"` at the top of test files, but in ESM, `import` statements are hoisted above top-level expressions. `@sponsee/db` was therefore imported *before* the env var was set, causing PGlite to create a filesystem database (`.pglite-data`) instead of in-memory. Multiple test files racing on the same directory caused `RuntimeError: Aborted()` WASM crashes.
- Fix: added `scripts/vitest-setup.ts` that sets `VERCEL=1` before any test module loads, and updated `package.json` test script to run API tests sequentially (`fileParallelism: false, maxWorkers: 1`) with this setup file. Web tests run separately with `jsdom`.

**P2 — editAndSend race** (`apps/api/src/routers/chase.ts`)
- Combined snapshot update + status claim into a single atomic `UPDATE … SET status = "approved", subjectSnapshot = ?, bodySnapshot = ? WHERE status = "awaiting_review"`.
- Added test proving a losing concurrent request cannot overwrite the winner's snapshots.
